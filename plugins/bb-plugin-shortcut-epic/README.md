# Shortcut Epic for bb

`bb-plugin-shortcut-epic` adds a full-page dependency graph for the Epic
configured by `shortcut-agent`. It is a companion to the CLI, not a second
Shortcut workflow implementation: the backend bundles the CLI's v4 client and
story classification logic.

The graph:

- draws blocking relations from prerequisite to dependent, left to right
- ring-highlights work in a Started state, including active work that later
  becomes blocked
- distinguishes ready, blocked, active, and other work
- fades completed Stories without removing useful graph history
- identifies unresolved blockers outside the configured Epic
- warns instead of hanging when pre-existing Shortcut data contains a cycle
- refreshes every 60 seconds and on demand

Story cards link to Shortcut. The panel is read-only; agents should keep using
`shortcut-agent` for claims and lifecycle mutations.

## Install from this repository

bb supports plugins in a repository subdirectory. From the repository root,
install this plugin directly by path:

```sh
bb plugin install ./plugins/bb-plugin-shortcut-epic
```

The root `.bb/plugins.json` also indexes the plugin, so this equivalent form is
available:

```sh
bb plugin install path:. --plugin shortcut-epic
```

Both are path installs: bb registers the working directory in place. Use
`bb plugin dev` during development so frontend saves rebuild and reload
automatically.

Install the plugin from Git with the collection entry:

```sh
bb plugin install \
  git:https://github.com/andreasmcdermott/shortcut-agent-cli.git@main \
  --plugin shortcut-epic
```

The explicit subdirectory form works without the collection manifest:

```sh
bb plugin install \
  git:https://github.com/andreasmcdermott/shortcut-agent-cli.git@main \
  --subdirectory plugins/bb-plugin-shortcut-epic
```

The checked-in `dist/` bundle lets Git installs load without installing this
package's development dependencies.

## Configure

Open **Extensions → Plugins → Shortcut Epic** and set:

- **Shortcut API token** — required unless the bb server process already has
  `SHORTCUT_API_TOKEN`; stored as a bb secret and never sent to the frontend
- **Default bb project** — optional; use it when several bb projects contain a
  `.shortcut-agent.json`, or when the panel has no project context

The secret setting is recommended for desktop bb. Exporting a token in an agent
terminal does not retroactively add it to an already-running bb server process.

The selected bb project must contain a valid `.shortcut-agent.json` generated by:

```sh
shortcut-agent init --epic 12345
```

The plugin first checks the project root and then performs a bounded nested
lookup. A project with more than one config is intentionally rejected because
there is no safe way to infer which Epic the panel should display. The ignored
`.shortcut-agent.local.json` is not read: agent identity is unrelated to this
read-only Epic view.

If no default project is selected, the plugin auto-discovers all bb projects.
Exactly one configured project is selected automatically; zero or multiple
matches produce an actionable configuration message.

After changing settings, bb automatically retries a plugin waiting for
configuration. A manual reload is also available:

```sh
bb plugin reload shortcut-epic
```

## Develop

```sh
cd plugins/bb-plugin-shortcut-epic
npm install --include=dev
npm test
npm run typecheck
npm run build
bb plugin install .
bb plugin dev
```

The plugin is pinned to the SDK of the bb release that scaffolded it. After a
bb upgrade, verify the pin before relying on newly added SDK surfaces:

```sh
bb plugin types --check
```

The distributable build contains:

- `dist/server.js` and metadata — API/config discovery plus graph projection
- `dist/app.js`, `dist/app.css`, and metadata — the bb nav panel

Dependency layout is covered by `graph.spec.ts`, project-config/API projection
by `server.spec.ts`, and nav-panel rendering plus refresh behavior by
`app.spec.tsx`. The repository's CLI tests remain independent and continue to
run with the root `npm test`.
